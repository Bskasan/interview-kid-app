# i18n — Turkish + English

## What the user sees

1. First launch: the app opens in the device language if it is Turkish or English,
   otherwise in Turkish. Every screen — Home, Exercise (including question prompts and
   answer captions), Result, all accessibility labels — is fully in that language.
2. The Settings tab (Ayarlar) shows one toggle: a small pill track with "TR" on the left and "EN" on the
   right, and a round white knob carrying the current language's flag (🇹🇷 or 🇬🇧). The current
   side's code label is bold and dark, the other one gray; the knob sits on the current side.
3. Tapping anywhere on the toggle slides the knob to the other side with a springy motion (the
   flag crossfades to the new one at mid-slide) and plays the short transition (~0.85 s): a
   cream full-screen overlay fades in, the mascot bounces gently with "Dil değişiyor…" /
   "Changing language…" shown in the NEW language, the app switches underneath, and the
   overlay fades out. Taps during the transition are ignored — a rapid double-tap toggles
   once. With reduced motion enabled the knob jumps and the language swaps instantly with no
   overlay.
4. The choice is remembered: killing and relaunching the app restores the chosen language
   (a sub-second flash of the device language can occur on cold start while storage loads).
5. In English, the timer's spoken label pluralizes correctly ("1 second left" / "12 seconds
   left"); Turkish uses its single form.

## How it works in code

- **`src/locales/tr.json` / `en.json`** — one file per language; top-level keys are the six
  namespaces (`common`, `home`, `exercise`, `result`, `errors`, `questions`). Interpolation
  uses `{{placeholder}}`; the only plural pair is `exercise.timeLeft_one/_other`.
- **`src/i18n/index.ts`** — creates the singleton: synchronous init (`initAsync: false`,
  bundled resources), device-locale detection via `expo-localization` `getLocales()`,
  `supportedLngs: ['tr','en']`, `fallbackLng: 'tr'`. Also installs the `intl-pluralrules`
  polyfill behind a `typeof Intl.PluralRules` guard (Hermes lacks it; Node does not).
  Imported first in `app/_layout.tsx` so translation is ready before any render.
- **`src/i18n/i18next.d.ts`** — `CustomTypeOptions` typed from `tr.json`: unknown keys fail
  `tsc`.
- **`src/store/settingsStore.ts`** — persisted zustand store (`settings-v1`); `language:
'tr' | 'en' | null` (null = follow device). `setLanguage` flips i18next immediately;
  `onRehydrateStorage` re-applies a stored choice on launch.
- **`src/components/LanguageSwitch.tsx`** — the single toggle (ADR 0043): one `Pressable`
  (110×52dp track + 60dp overhanging knob = a 60dp-tall target) with
  `accessibilityRole="button"`, a translated label naming the current language and the tap
  action (`common:languageToggleA11y.{tr,en}`), and `accessibilityState {disabled, busy}`
  while a transition runs. The knob position is a reanimated shared value driven by
  `pending ?? active` (`withSpring(motion.spring)`; reduced motion jumps); the two flags
  crossfade via worklet interpolation over progress 0.42–0.58, so the swap is frame-exact at
  mid-slide with no timers. The flag stays an isolated `Flag` subcomponent (one-function swap
  to bundled SVGs if a device renders flag emoji as letter pairs). On tap it only writes the
  target language into the transition store; reduced motion calls `setLanguage` directly
  instead.
- **`src/store/languageTransitionStore.ts`** — transient `{ pending }` store (never
  persisted); `begin` is idempotent while a transition runs (double-tap backstop).
- **`src/components/LanguageTransitionOverlay.tsx`** — root-sibling absolute overlay in
  `app/_layout.tsx`, above the error banner (zIndex 20 vs 10). Timeline from
  `LANGUAGE_TRANSITION` (`src/constants/timing.ts`): fade in 250 ms → `setLanguage` fires at
  300 ms under full opacity (plain `setTimeout`s, cleared on unmount) → fade out from
  600 ms → unmount at 850 ms. The overlay line uses `i18n.getFixedT(target)` so it renders
  in the target language and cannot flip mid-hold (`key={pending}` freezes the shell per
  transition).
- **`src/data/questions.ts`** — language-neutral question bank: namespaced keys per
  set/question (`shapes.q1.prompt`, …), typed
  `labelKey`/`a11yKey` into the `questions` namespace, shape options derive their spoken
  label from `questions:shapeOption` + color/shape token entries (word order per language).
  `optionLabel(option, t)` / `optionA11yLabel(option, t)` are the accessors.
- **`src/api/lessons.ts` + `src/types/lesson.ts`** — the Lesson model carries
  `lessonNumber` + `author`; the map row and bubble compose the title at render time, so cached data
  is never language-stale. Persister buster bumped to `lessons-v2`.
- Components use `useTranslation(namespace)`; screens pass typed keys only.

## Edge cases handled

- Unsupported device language → Turkish (fallback), not a blank or mixed UI.
- Language switch with a populated, persisted lesson cache → titles re-render from neutral
  fields; no refetch needed, works offline.
- Missing key in one language → build-time failure: `tsc` (key not in tr.json) or the
  parity test (`__tests__/locales/messages.test.ts`: identical key sets, no empty values,
  identical `{{placeholders}}` per key).
- Question content integrity per language → `__tests__/data/questions.test.ts` resolves
  every prompt/option in both locales and asserts four unique spoken labels per question.
- Plural correctness on Hermes → runtime-guarded polyfill; device checklist covers "1
  second left".
- Double-tap / tap during transition → the toggle disables while pending (spoken as
  busy/disabled), the opaque overlay swallows touches, and `begin` is idempotent — three
  independent layers; a rapid double-tap can never bounce the language back.
- App backgrounded mid-transition → JS timers pause and resume on foreground; the sequence
  completes then. Killed inside the first 300 ms → the choice wasn't saved yet; re-tap.
- Error banner during transition → covered by the opaque overlay for the sub-second, still
  mounted and visible after fade-out.
- Literal-string regressions → `eslint-plugin-i18next` (`no-literal-string`, default
  options) errors on hardcoded JSX text under `app/`/`src/`; emoji/glyph constants are
  exempt by design.

## How to test manually

1. Set the device language to English → app opens in English; to Turkish → Turkish; to any
   third language → Turkish.
2. Tap the toggle in Settings: the knob starts sliding at once (flag crossfades mid-slide), the
   overlay fades in with the mascot and the "changing language" line in the NEW language,
   then fades out with everything switched — lesson titles and the offline banner included
   (enable airplane mode to see it). Total feels under a second. Toggle back the other way
   and both directions look right.
3. During the transition, tap rapidly anywhere (the toggle, cards) → nothing reacts until the
   overlay is gone; a fast double-tap on the toggle switches once, never twice.
4. Enable "Remove animations" (Android accessibility) → tapping the toggle swaps instantly:
   knob jumps, no overlay at all.
5. Enter a lesson in English: prompt, captions and (with TalkBack) spoken option labels are
   English; switch back in Settings and re-enter: Turkish.
6. Choose English, kill the app, relaunch → still English.
7. With TalkBack: the toggle announces as a button with "Dil: Türkçe. İngilizceye geçmek
   için dokun." (and the English equivalent after switching); during the transition it is
   announced busy/disabled. The timer announces "N seconds left" / "Kalan süre N saniye".
8. Check the knob's flag renders as a flag (not a "TR"/"GB" letter pair) on the test device,
   in both positions.
