# 0023 — Typed-routes generation for typecheck (`expo customize tsconfig.json`)

Status: accepted
Date: 2026-08-19

## Context

`tsconfig.json` includes `.expo/types/**/*.ts` and `expo-env.d.ts`, both gitignored and
generated by the dev server (Expo Router `typedRoutes` is enabled). On a fresh clone — and
in CI — `tsc --noEmit` fails before anything else runs because the route declarations don't
exist yet. The README previously papered over this ("run `npx expo start` once"), which is
not automatable.

## Decision

Add a `typegen` script running `npx expo customize tsconfig.json` and make `typecheck` run
it first (`npm run typegen && tsc --noEmit`). `expo customize` bootstraps the TypeScript
prerequisite and performs a one-shot typed-routes generation without starting Metro or a
dev server: verified locally that it regenerates `.expo/types/router.d.ts` and
`expo-env.d.ts` in ~2 s, leaves an already-configured `tsconfig.json` byte-identical, and
runs non-interactively. Typecheck is now self-sufficient on any machine, so it can stay the
first (fastest-failing) step of `check` and of CI.

## Alternatives considered

- **Run the android export before typecheck** — `expo export` also generates the types, but
  it is by far the slowest step; ordering the pipeline around it would delay every type
  error by minutes.
- **Commit the generated files** — they drift with the route tree and the SDK; a stale
  committed `router.d.ts` produces confusing false positives, and the Expo template
  gitignores them deliberately.
- **Disable `typedRoutes`** — removes compile-time checking of `router.push`/`replace`
  targets, which this app actively relies on; solving a CI ordering problem by deleting a
  safety net is backwards.
- **Keep the manual "run expo start once" README note** — works for a human, useless for
  hooks and CI.

## Consequences

- `typecheck` works identically locally, in the pre-commit hook, and in CI, with a ~2 s
  overhead per run.
- The behavior of `expo customize` (generate-if-configured, don't prompt) is an Expo CLI
  implementation detail; an SDK upgrade that changes it would surface immediately as a
  loud `check` failure, not silent drift.
